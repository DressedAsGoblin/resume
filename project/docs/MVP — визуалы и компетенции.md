# MVP: визуальные материалы и компетенции

## Принятое направление

- QAQC — центр контроля данных, связанный с каждым проектом. Это общая инженерная связь, а не утверждение об историческом использовании системы QAQC во всех работах.
- Отдельная направленная связь СИГНАЛОГИ → XEEK показывает применение результатов исследования в конкурсном прототипе.
- Третий вид линии — маршрут героя в порядке 1 → 2 → 9. Он не подменяет технологические зависимости.
- Сумка компетенций показывает опыт специалиста, подтверждённый кейсами. Повторное применение навыка добавляет подтверждение, а не дубликат. Первое раскрытие навыка в интерфейсе не означает, что специалист впервые освоил его именно тогда.

## Как отбираются визуалы

Для карточки достаточно двух содержательных иллюстраций: проблематика и основной результат. Сначала короткий вывод, затем изображение с пояснением. Дополнительные материалы доступны отдельно. Ниже — предварительный выбор на основе просмотра исходных изображений, а не только названий слайдов. Новые оформленные иллюстрации ещё не созданы.

### QAQC

Источник: `ANNUAL REPORT QAQC_full.docx` в зеркале sources проекта g-p-6a4789530c1c8191b34e3282ecf79a3f.

- **Проблематика:** на основе рисунка 19 «Группы тестов ... связи между узлами данных» построить упрощённую схему связей керна, ГИС, сейсмики и модельных свойств. Показать, что корректность отдельного источника не обеспечивает согласованность связей. Иллюстративное противоречие подписать как пример, не выдавать за результат реальной проверки.
- **Результат:** на основе рисунка 2 «Блок-схема архитектуры QA/QC» показать короткую цепочку: загрузка / преобразование → хранение → проверки → анализ / визуализация. Не перегружать именами классов из исходной архитектуры. Это объяснение результата команды, не доказательство личного написания компонентов руководителем. TRL 6 — по текущей пользовательской редакции истории.
- Исходные изображения просмотрены: `source_audit/media_review/qaqc-figure-19-946-0.png`, `qaqc-figure-2-202-0.png`.

Компетенции героя:
- методология контроля геоданных;
- перевод предметной задачи в требования к IT;
- критерии качества и проверки результатов;
- MBSE и системное проектирование — по уточнению пользователя.

Не добавлять личную разработку БД, ридеров или Python-кода только потому, что они есть в системе команды.

### СИГНАЛОГИ

Источник: `мои проекты.zip :: проекты/Кононов. Регрессия/Сигналоги. ТПУ 21.10.pdf`.

- **Проблематика:** страница 12 показывает 10 000 синтетических кривых и задачу группировки. Для новой композиции выбрать несколько репрезентативных форм, объяснить трудность визуального сопоставления. Масштаб 10 000 относится к синтетическому эксперименту, не к объёму реальной работы петрофизика за один просмотр.
- **Результат:** страница 29 «Три кластера»: кривые-представители, карта кластеров и геологическая основа. Сократить до сравнения «распределение геологических тел / группировка сигналов»; не смешивать кластерные метки с фациальными классами. На странице 32 прямо отмечено влияние вертикального положения объекта — сохранить это ограничение в подписи.
- Просмотрены рендеры: `source_audit/media_review/signalogi-page-12.png`, `signalogi-page-29.png`. Текст ограничений: `source_audit/023.txt`, страница 32.

Компетенции героя:
- сравнение формы сигналов: DTW;
- спектральная обработка: FFT;
- кластеризация: KMeans / Agglomerative Clustering;
- геологическая проверка и интерпретация результатов ML.

### Keep Geoscience Weird / XEEK

Источник: `мои проекты.zip :: проекты/XEEK PRESENTATION (2) (2).pptx`.

- **Проблематика:** на слайде 8 — целевая скважина и набор сравниваемых кривых; на слайдах 3–5 сформулирована задача картирования сходных регионов. Показать короткую связку «опорная скважина → поиск сходных сигналов → зоны на карте».
- **Результат:** карта сходства и выбранные аналоги со слайда 8. Красная точка обозначает целевую скважину; меньшая величина метрики означает большее сходство. Эти смыслы сохранить при переоформлении. Слайд 7 содержит синтетический пример — использовать только с этой пометкой. Скриншот окна настройки можно оставить в дополнительных материалах, а не в основной истории.
- Просмотрены исходные встроенные изображения: `source_audit/media_review/xeek-slide-8-image-0.png` (карта), `xeek-slide-8-image-1.png` (кривые), `xeek-slide-8-image-2.png` (интерфейс), `xeek-slide-7-image-0.png` (синтетическая карта).
- Общую иллюстрацию разложения сигнала из слайда 6 не брать основным визуалом: она объясняет метод, но хуже показывает собственный результат проекта.

Компетенции героя:
- перенос исследовательского подхода в прикладной прототип;
- вычислительные эксперименты;
- программное прототипирование;
- картирование зон сходства по ГИС.

Связанные навыки СИГНАЛОГОВ отмечать как повторно применённые. Не добавлять SOM как личную компетенцию только из-за наличия слайда 9: личный вклад в его реализацию не установлен.

## Правила переоформления

Фон, типографика, композиция, подписи и декоративные элементы соответствуют миру интерактивного резюме. Графики результатов сохраняют геометрию данных, величины, оси, единицы и легенду; палитра не должна менять смысл групп. Если точное восстановление из данных невозможно, переоформляется окружение исходного графика. Схематическое объяснение помечается как схема. Количественные результаты не перерисовываются генеративно. Для любого нового визуала сохраняется ссылка на исходный слайд / рисунок. Основные тексты первых трёх кейсов не изменять без запроса пользователя.
